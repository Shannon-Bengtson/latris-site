Pipelines

Use a model in a pipeline.

A model you have built and argued for in Latris can be called from a script, a notebook or a scheduled job. It says which values a caller may set and which results it returns, it runs without recording anything, and every result says which version of the model produced it.

1. Declare the contract

A contract names the model's inputs (what a caller may set, with units, a default and the range the value is valid over) and its outputs (what comes back). It is drafted from the model, then pruned: every input is a promise to whoever calls it, so expose only what a caller should set. 

latris contract init equation_model   # draft it from the model
latris contract show                  # inputs, outputs, units, valid ranges
latris contract input equation_model "Roughness" --name mannings_n
latris contract check                 # does it still fit the model?

The names are the interface. A caller writes flow_depth, and the name stays when the factor behind it is renamed. In the app, the same thing is under Communicate & Use → Use.

2. Run it

import latris

model = latris.load("path/to/project", ref="Signed off")

result = model.predict({"flow_depth": 2.5})
result["outputs"]["discharge"]["value"]    # 24.08
result["outputs"]["discharge"]["units"]    # "m**3/s"
result["warnings"]                         # [] here
result["provenance"]["commit"]             # the version that produced it

From a terminal, latris predict --set flow_depth=2.5 does the same, and latris --json predict … prints the whole result as one JSON object. Nothing is written to the project: a prediction is a call, not an analysis recorded for the report.

  • An input you leave out takes the contract's default, or the model's own value.
  • Units are converted. "250 cm" is accepted where the input is in metres; seconds are refused.
  • A value outside its valid range is used as given, and flagged. The result carries a warning that it is an extrapolation. Nothing is clamped silently.

3. Pin a version

A Latris project is a git repository, so a pipeline can run the model exactly as it was when someone signed it off, whatever has changed since. ref takes a milestone's name, a version's name or a commit.

Predict never refuses a version for being unreviewed. It reports the review state with the result, and a pipeline that wants a gate asks for one: model.predict(inputs, require="approved") or --require approved.

4. Move to a newer version safely

latris contract diff "Signed off"     # that version against the latest
VerdictWhat it means for a caller
BreakingAn input or output was removed or renamed, its units changed, or an input became required. The command exits 1, so a pipeline can refuse the upgrade.
CompatibleSomething optional was added, or a default or valid range changed. The caller still works.
Internal onlyThe contract is the same, but the model behind it changed, so the same inputs may give different outputs.

Which models

Honest limits

  • Inputs are single values. A caller who needs a time series loops over values in their own code.
  • A prediction returns the model's point answer. Run the model's Monte Carlo analysis for the spread.
  • There is no hosted endpoint: a pipeline clones the project and calls the library. Pin the latris version as well as the model's.
  • A contract doesn't make a model right for a use it wasn't built for. Valid ranges are how a caller learns it has left the ground the evidence covers, so state them.
