Open source

Built on an open engine.

The modelling engine behind Latris is open source (Apache-2.0): a deterministic, git-native Python CLI and library, designed to be driven from a terminal or by an agent. The hosted app runs the same engine underneath, with the same schema, history and analyses.

pip install "latris[data,quant]"

Python 3.11+ and git 2.40+. Status: alpha.

Design

How the engine is built.

Every project is a git repo

Every change is an inspectable, reversible commit made as you. Latris enforces a real identity and never commits as an AI.

Evidence is data

Citations, checks, assumptions, decisions, challenges and sign-offs are structured records in plain YAML, not annotations.

AI returns proposals

AI output is structured and validated, never free-form edits. Keys live in your OS keyring, never on disk.

Inspectable by design

Black-box predictors are excluded on purpose: a model type is admitted only if its reasoning stays inspectable.

For agents

Drive it from Claude Code or any agent, with no API key.

Your agent drafts, you approve, and every step stays on the record. Agents start at llms.txt, which maps the documentation and the working rules. latris docs prints the agent guide from the installed package with no network, and latris capabilities lists what's available.

Any of the engine's AI prompts can be answered by the agent already in the loop instead of a vendor API (latris ai task emit and apply), with the same validation and approval gates.

Working in Claude or ChatGPT instead? The connector is simpler.

Pipelines

Call a model from your own code.

A finished model can declare a contract (the inputs a caller may set and the outputs it returns) and be run from a script or a scheduled job. It records nothing, it can be pinned to the version a person signed off, and every result says which version produced it. 

import latris
model = latris.load("path/to/project", ref="Signed off")
model.predict({"flow_depth": 2.5})

Quickstart

A model in a few commands.

latris init volunteers --question "Why are volunteers leaving?"
cd volunteers
latris build --spec model.yaml                # factors, links, sources in one step
latris check handover                         # what's left before a board sees it
latris export md --pack client -o report.md   # report with a Mermaid diagram
latris link                                   # a link that opens the full report

The full walkthrough is in the README, and every command is exercised end to end in the worked example transcript. What changed recently is in the changelog.
