Bayesian networks

Probabilities you can trace back to where they came from.

A discrete Bayesian network puts probabilities on the states of each factor, conditional on its causes, and updates them as evidence arrives. Latris follows the tradition of defensible, partly expert-elicited networks: every cell records whether it was elicited or learned, and each table can say how well it's known.

At a glance

An arrow claimsThe parent's state changes the probability distribution of the child's state. Together with the child's conditional probability table, the arrows define the joint distribution.
NumbersDiscrete states for every factor and a conditional probability table for each.
Causal standingObservational: posterior probabilities given evidence. A causal reading of the arrows is an assumption the modeller makes, not something the network establishes.
In LatrisExact inference; hard, soft and likelihood evidence; most likely explanations; parameter learning that respects elicited values; one-way sensitivity; Monte Carlo over uncertain tables.

Where it comes from

Bayesian networks were founded by Pearl (1988). Fenton and Neil (2018) set out the practice closest to Latris's: networks built with domain experts, numbers that have to be defended, and causal structure argued rather than mined from data. Soft evidence follows Jeffrey's (1965) rule for updating on uncertain observations.

In environmental and natural-resource modelling, Bayesian networks are a well-established decision-support method, and the field has its own good-practice guidance (Marcot et al. 2006; Chen and Pollino 2012). That guidance stresses a clear model purpose, a documented conceptual model, transparent parameterisation from experts and data, sensitivity analysis, and documentation a reviewer can follow. Latris records each of those as part of the model rather than in a separate report, though it doesn't cover every step: see the limits below.

What practitioners know to watch for

The known problemWhat Latris does
Where did this number come from? A finished network rarely shows which probabilities were elicited, which were learned, and from what. Provenance is kept per cell. Learned rows are marked as data-derived, and learning never overwrites a row a person elicited.
False precision. A single number in each cell hides how little is known about it. Any table, or any row, can be marked as "worth about n observations". Monte Carlo over those Dirichlet distributions gives the target probability with 50% and 95% intervals, and names the tables that drive the spread.
Elicitation burden. Tables grow exponentially with the number of parents, and experts can't fill them reliably. Noisy-OR canonical models for binary effects with independent binary causes: one probability per cause plus a leak, instead of a full table.
Uncertain observations. Real evidence is often "probably", not "yes". Soft evidence by Jeffrey's rule (the node ends up at the stated probability) and likelihood evidence (relative weights), alongside hard evidence. The report says which kind was entered.
Structure mined from data. Learned structures are hard to defend causally and unstable on small samples. Structure learning is excluded by design. The structure is argued link by link, with sources, like any other Latris model; only the parameters can be learned.
Discretisation drives results. Where the state boundaries fall changes the answer. The modeller defines the states. Binning a data column is a recorded, reversible step in the data workspace, and sensitivity analysis shows which tables the result depends on.

What Latris implements

  • Exact inference by variable elimination (via pgmpy): posterior marginals for every node given the evidence.
  • Evidence: hard, soft (Jeffrey's rule) and likelihood evidence, per node.
  • Most likely explanation: the most probable joint states (MPE, or MAP over chosen nodes), with how much more likely each state is than its runner-up.
  • Parameter learning from discrete data by maximum likelihood or a Bayesian estimator (BDeu prior), protecting elicited rows.
  • Noisy-OR canonical tables.
  • Sensitivity: one-way (tornado) sensitivity of a target over table cells, with each cell's provenance shown; probabilistic sensitivity by Monte Carlo over uncertain rows.

What it doesn't do

  • Variable elimination only: no junction tree or belief propagation. Marginals, not joint posteriors (apart from the most-likely-explanation query).
  • Discrete variables only. No continuous or hybrid networks, and no dynamic (time-sliced) networks.
  • No structure learning, by design.
  • No predictive validation against held-out data, and no value-of-information (EVPI) analysis yet.
  • Noisy-OR needs binary effects and binary causes.

On the ladder of causation

Latris uses Bayesian networks for the first rung: what is likely, given what has been observed. It doesn't compute interventional (do-operator) queries on them. If you need to know what to adjust for to estimate an effect, that's a question for a causal DAG on the same factors.
