Models

Which model should you build?

Latris has fifteen model types in seven families: systems, causal inference, evaluation, risk and safety, decisions, arguments and equations. They're not fifteen apps. Every one is built from the same factors, links and sources, so the choice is about the question you need answered, not about which drawing tool to open. This guide is the reasoning behind the Formalise step in the app.

Short answer: pick by the question, using the table below. If the question is how something works or what drives an outcome, start with a causal loop diagram: it is the cheapest honest answer, and the systems and causal types build on it. If it's a choice, a risk, a programme, a case to argue or a calculation, there is a model type made for that question. Whichever you pick, you never redraw: the same factors, sources and challenges carry across when you add another.

Seven families, one evidence base

Every model type is made of the same things: factors and links, where each claim carries its sources, for and against. What differs is what a link means (a cause, a failure path, a reason, a formula) and how much you commit to. Within a family the types form a ladder, from qualitative to quantitative, and a model climbs a rung without being redrawn.

FamilyModel typesWhat it's for
SystemsCausal loop diagram → fuzzy cognitive map → system dynamicsHow a system with feedback works, which forces dominate, and how it behaves over time
Causal inferenceCausal DAG → Bayesian networkWhether an effect can be estimated, and how likely each outcome is given what you know
EvaluationTheory of change, with process tracing and impact estimatesWhether a programme's logic holds, step by step, and what it changed
Risk and safetyBow-tie, fault tree, event treeHow a failure comes about, what protects against it, and what follows
DecisionsMulti-criteria decision analysis; decision tree → Markov cohort modelWhich option to choose: on several criteria, under uncertainty, or over years
ArgumentsAnalysis of competing hypotheses; argument mapWhich explanation survives the evidence, and whether a case holds up
EquationsEquation modelWhat sourced formulas give for these inputs, with units checked

The evidence discipline is identical in every family: a claim without a source is a visible gap, a source that argues against it stays on the record, and the report says which methods were used and what they can't do. That's what makes any of them defensible, and it's why the choice of model type is a choice about the question and about how much you can commit to.

Systems

For questions about how something works as a whole: what feeds back on what, which forces dominate, and how the system behaves over time. The three types are one diagram at three levels of commitment: direction only, soft weights, then stocks, flows and equations.

Causal loop diagram (CLD)

"How does this work? What feeds back on what?"

  • Reach for it when: you're aligning people on the mechanism, hunting for feedback loops and leverage points, or scoping a mess before any data work.
  • You'll need: argued links, each arrow a claim someone will defend, with a source where one exists.
  • What you get: the structure of the problem: loops, polarity, where an intervention would bite. No numbers.
  • Honest limit: arrows are argued, not estimated. A CLD shows where an effect runs, never how large it is.

Fuzzy cognitive map (FCM)

"Which forces dominate, roughly?"

  • Reach for it when: you want more than arrows but can't defend full equations: expert judgement in the form "this pushes hard, that resists weakly".
  • You'll need: signed, weighted links (from −1 to +1) and, for scenarios, which factors to hold fixed.
  • What you get: steady-state tendencies under interventions: the direction and rough strength of the net effect.
  • Honest limit: semi-quantitative by design. It says which way the water flows and roughly how fast, not what happens in year three.

Scientific basis: what the arrows mean, lineage, known pitfalls, references →

System dynamics (SD)

"How will this behave over time if we intervene?"

  • Reach for it when: the behaviour over time is the question (accumulation, delays, tipping points, capacity trade-offs) and you're prepared to defend equations and parameters.
  • You'll need: stocks and flows with units that check out, scenario definitions, and, for uncertainty, which parameters are uncertain and by how much.
  • What you get: trajectories under scenarios, Monte Carlo uncertainty bands, which values the result is most sensitive to, which feedback loop dominates when (the Loops That Matter method), and charts a board can interrogate. Every parameter carries where it came from.
  • Honest limit: the most commitment in this family. A precise answer to the wrong structure is worse than a vague one, so build the CLD first and quantify it once the structure has survived review.

Causal inference

For questions about a specific effect: can it be separated from confounding, and how likely is each outcome given what has been observed? Both types need an acyclic graph, and a causal loop diagram's factors and evidence carry straight across.

Causal DAG

"Can that effect even be estimated, and from what data?"

  • Reach for it when: you have (or are about to collect) observational data and someone will ask whether the estimate is confounded.
  • You'll need: a graph you can defend, every edge a causal claim, plus clarity about what could be measured.
  • What you get: an identification strategy: d-separation checks and valid adjustment sets, meaning what to control for, or a statement that no small set suffices. With a dataset, the effect itself by adjusted regression, shown beside the unadjusted association.
  • Honest limit: identification comes first, and an estimate is causal only if the graph leaves out no common cause and the regression's form is right; the report says so every time. No counterfactuals.

Scientific basis: what the arrows mean, lineage, known pitfalls, references →

Bayesian network (BN)

"How likely is each outcome, and what would change my mind?"

  • Reach for it when: the question is decision-making under uncertainty over discrete conditions (pass/fail, present/absent, low/medium/high) and evidence arrives piece by piece.
  • You'll need: states for each factor and conditional probability tables, elicited from experts, learned from data, or mixed. Latris keeps the provenance of every cell.
  • What you get: exact probabilities that update as you enter evidence, including uncertain evidence ("80% sure"); the most likely explanation for what you observed; which unknowns matter most; and, when the tables are estimates, how sure each probability is.
  • Honest limit: discrete states and exact inference on modest networks. If your variables are continuous and tightly coupled over time, system dynamics is the better fit.

Evaluation

For programmes and policies: how the intervention is supposed to lead to its impact, how well each step is evidenced, and, with data, what changed when it started.

Theory of change

"How is this programme supposed to work, and which steps are taken on trust?"

  • Reach for it when: you're designing or evaluating a programme or policy, and a funder or evaluator needs to see which steps of its logic are evidenced and which are assumed.
  • You'll need: factors placed on levels from activity through outputs and outcomes to impact, the links between them, and the assumptions each step relies on. For an impact estimate, a dataset of the outcome over time.
  • What you get: every pathway from an activity to an impact, link by link: checked, cited, untested or contested, with its assumptions. Process tracing weighs the evidence for each step (hoop and smoking-gun tests) and gives a confidence per pathway. With data, an impact estimate by interrupted time series or difference-in-differences, with its validity checks.
  • Honest limit: the pathway view shows where the chain is unsupported, not how large an effect is. An impact estimate holds only under its design's assumptions (nothing else changed at the same time; the groups were on parallel trends), and each failed check is reported with the result.

Risk and safety

For one undesired event: the barriers around it, the failures behind it and the sequences after it. Each type takes point values or ranges, and every probability and frequency carries where it came from.

Bow-tie

"What stands between this hazard and harm, and where is it thin?"

  • Reach for it when: you need to show, for one hazardous event, what could cause it, what could follow, and the barriers in between, for a risk register, an operator or a regulator.
  • You'll need: one top event, its threats and consequences, and the barriers on each line with their type, status and owner. For numbers, threat frequencies and barrier failure probabilities, each with its source.
  • What you get: lines that rest on one barrier or none, barriers shared between lines, escalation factors with no control, and barriers nobody owns. With numbers, the layer-of-protection frequency of the top event and of each consequence, and how much each barrier buys. With ranges, Monte Carlo over them.
  • Honest limit: barriers are assumed to fail independently, and frequencies are order-of-magnitude, as in any layer-of-protection analysis. There is no severity scoring and no risk matrix.

Scientific basis: methods, references, limits →

Fault tree

"What combinations of failures cause this, and how likely is it?"

  • Reach for it when: the question is how one undesired event can come about, and which failures matter most to preventing it.
  • You'll need: the top event broken down through AND, OR and k-of-n gates to basic events, and a probability for each basic event with its source.
  • What you get: the minimal cut sets, the single points of failure, the exact top-event probability, and which events matter most (Birnbaum, Fussell–Vesely and risk-achievement-worth importance). With ranges, how sure the probability is and which inputs drive it.
  • Honest limit: static, and basic events are assumed independent: there is no common-cause model, and no NOT or sequence gates.

Scientific basis: methods, references, limits →

Event tree

"Once this happens, how does it play out, and how often does it end badly?"

  • Reach for it when: you're following one initiating event forward: which safety functions work or fail, in what order, and how often each ending results.
  • You'll need: one initiating event and its frequency, ordered yes/no headings, an end state for every path, and a probability for each branch, conditional on earlier answers where it depends on them.
  • What you get: a check that the tree is complete, the probability and yearly frequency of each sequence and end state, and the sequences that dominate. With ranges, Monte Carlo over them.
  • Honest limit: branches are yes or no; headings depend on each other only where you state a conditional probability; and heading probabilities are entered by hand, not linked live to a fault tree.

Decisions

For a choice between options. Which type depends on what makes the choice hard: several things to trade off, an outcome that depends on chance, or costs and benefits that build up over years.

Multi-criteria decision analysis (MCDA)

"Which option should we choose, given what we care about?"

  • Reach for it when: options have to be judged on several things at once (cost, risk, fairness, time) and you need to show how the choice was reached.
  • You'll need: the options, the criteria with their weights and scales (worst and best), and a score for each option on each criterion, with its source.
  • What you get: the ranking with each criterion's contribution, the options that are dominated, and how far each weight would have to move before the top choice changes.
  • Honest limit: additive and linear. Weights are judgements, and they mean nothing apart from their scales. No AHP or outranking methods.

Scientific basis: methods, references, limits →

Decision tree

"What should we do, given what we don't know, and is it worth finding out more first?"

  • Reach for it when: the outcome of a choice depends on chance, and someone will ask whether to commission another study before committing.
  • You'll need: the decisions, the chance events with their probabilities, and a payoff for each ending, with sources.
  • What you get: the best strategy by expected value, what perfect information on each uncertainty would be worth, and the probabilities at which the best choice flips. With ranges on the inputs, a probabilistic sensitivity analysis: how often each choice is best, and the value of information input by input.
  • Honest limit: risk-neutral: expected value, with no utility function. It values perfect information only, not an imperfect study.

Scientific basis: methods, references, limits →

Markov cohort model

"What does each option cost and achieve over years, and is the better one worth its price?"

  • Reach for it when: the options play out over years across a population moving between states, such as well, ill and dead, and the question is what each strategy costs and achieves.
  • You'll need: the states, transition probabilities per cycle for each strategy, a cost and a utility for each state, a discount rate and a willingness to pay.
  • What you get: the cohort's trace over time, discounted costs and outcomes per strategy, and incremental cost-effectiveness: ICERs, dominance and net benefit. With ranges, acceptability curves and the value of information.
  • Honest limit: memoryless: the chance of moving depends on the current state, not on how long the cohort has been in it. It is a cohort average, not a simulation of individuals.

Arguments

For reasoning that isn't a mechanism: weighing explanations against the evidence, or laying out a case so a reader can see what it stands on.

Analysis of competing hypotheses (ACH)

"Which explanation does the evidence fail to rule out?"

  • Reach for it when: there are several explanations for what happened, and the risk is settling on the first plausible one.
  • You'll need: the hypotheses, the evidence items with their credibility and relevance, and a rating of every item against every hypothesis, with the reasoning.
  • What you get: hypotheses ranked by the evidence against them (the least evidence against, not the most for), the items that don't discriminate, and the linchpins the conclusion turns on, with whether their sources were checked.
  • Honest limit: ratings are judgements and items are treated as independent. The ranking orders the hypotheses; it doesn't say how likely each one is.

Scientific basis: methods, references, limits →

Argument map

"Does the case hold up, and what does it rest on?"

  • Reach for it when: the deliverable is a case: a recommendation to a board, a position put to a regulator, a conclusion a reviewer will probe for its weakest premise.
  • You'll need: one conclusion, the claims for and against it, the reasons that work together or alone, the answers to each objection, and sources on the premises.
  • What you get: whether the conclusion stands, the premises it turns on, the objections still unanswered, and which premises rest on checked sources, unchecked sources or none.
  • Honest limit: qualitative: reasons aren't weighed numerically. A premise nobody argues against stands unless its sources contest it, and a map has one conclusion.

Scientific basis: methods, references, limits →

Equations

For a model that is a calculation: quantities joined by formulas from physics, engineering or the published literature, with every coefficient sourced.

Equation model

"What do the equations give for these inputs, and how far can the answer be trusted?"

  • Reach for it when: the model is a calculation, not a simulation: a physical law, an engineering relationship or a published parameterisation, such as a hydraulics formula, an emissions calculation or a dose-response curve.
  • You'll need: inputs and coefficients with their units, the formulas that join them, and for each formula and coefficient the source it came from and the range that source covers.
  • What you get: every quantity worked out, with the units checked so that a formula adding metres to seconds is refused; the result under named scenarios; how an output responds as one input moves; and, with ranges on the uncertain values, the spread of the result and what drives it. A value outside its valid range is reported as an extrapolation, never silently clamped.
  • Honest limit: units that balance don't make a formula right, and an empirical relationship is only as good as the study behind it. Formulas must be explicit: nothing is solved simultaneously, and there is no clock. If the behaviour over time is the question, that is system dynamics.

Scientific basis: methods, references, limits →

Uncertainty and sensitivity, in every quantitative type

Any number can carry a range instead of a single value, with the reason for the range on the record. Monte Carlo then runs the model across the ranges and reports the spread: for system dynamics, Bayesian networks, the three risk types and equation models. Decision trees and Markov models get a probabilistic sensitivity analysis: how often each choice is best, and what it would be worth to know each input. Global sensitivity analysis (Sobol indices, or Morris screening as a cheaper screen) says which inputs drive a result when they all vary together, for the risk types, decision trees, Markov models, system dynamics and Bayesian networks.

Using more than one

More than one model type can be right. Triangulating is a strength, not a mistake: a causal loop diagram for the mechanism plus a DAG for what could be estimated, or a fault tree that shares its events with the causal map around it. Because every model type sits on the same factors, links and evidence, adding one never means starting again, and the report records which you chose and why.

Some things Latris will never do. Black-box predictors you can run but can't inspect or defend (random forests, gradient boosting, neural networks) are excluded by design: a model type is admitted only if its reasoning stays inspectable.

If in doubt

Start from the question, not the method. If you can't yet say what kind of question it is, start with a causal loop diagram. It's the cheapest honest answer, it forces the arguments into the open, and its factors and evidence carry into whichever model type the question turns out to need. Add another when, and only when, a question arrives that needs more commitment. Choosing later, with evidence in hand, is a feature: you commit to numbers only when the stakes justify defending them.
